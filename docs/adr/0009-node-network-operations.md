# ADR-009. Сетевые операции узла: rtnetlink и отдельная таблица nftables

- **Статус:** принят (2026-10-28)
- **Обусловлен:** [спецификацией цикла A](../superpowers/specs/2026-10-20-novavpn-cycle-a-access-core-design.md), ТЗ §5, [измерениями S1](../spikes/2026-10-20-s1-s3-wireguard-netlink.md), [ADR-004](0004-wireguard-peer-apply.md)
- **Касается:** `internal/nodeagent/wg/link.go`, Ansible-роли `novavpn_node`, harness E2E

## Контекст

Узлу нужны WireGuard-устройство, адрес с маской пула, NAT и `ip_forward`.
Вызовы `ip`, `wg` и `iptables-save` из долгоживущего управляющего процесса
означали бы shell-операции вместо узкого типизированного API, против ТЗ §5.
Изменение общего ruleset хоста делает откат невоспроизводимым и затрагивает
чужие сетевые правила.

## Решение

1. Устройство и адрес настраиваются в процессе только через rtnetlink:
   `LinkAdd`, `LinkSetMTU`, `LinkSetUp`, `AddrReplace`, без `os/exec`.
   Используется `github.com/vishvananda/netlink v1.3.1`; конфигурация пиров
   формируется через `wgctrl v0.0.0-20241231184526-a9ab2273dd10` по ADR-004.
   Версии закреплены в `go.mod` и не обновляются молча.
2. Найденный интерфейс проверяется на тип `wireguard` **до любых изменений**
   MTU, состояния или адреса. Совпадение имени с чужим типом — ошибка.
   Только `LinkNotFoundError` разрешает создание; прочие ошибки поиска
   возвращаются с контекстом. MTU меняется лишь при отличии; новый или
   существующий интерфейс без флага UP поднимается через `LinkSetUp`.
   Адрес назначается идемпотентно через `AddrReplace`.
3. Маршрут пула отдельно не добавляется: connected route создаётся ядром
   при назначении адреса с маской пула. Дополнительный `RouteAdd` дублировал бы его.
4. `sysctl` и `modprobe wireguard` остаются отдельным root-шагом провижининга;
   агент не меняет параметры ядра и не загружает модули.
5. NAT и forward-политика принадлежат отдельной nftables-таблице `novavpn`.
   Чужие таблицы не читаются и не меняются; откат удаляет только эту таблицу.

## Последствия

- Для управления WireGuard достаточно `CAP_NET_ADMIN`, без привилегированного
  контейнера и `/dev/net/tun`: это показал S1. Агент проектируется без требования
  root; загрузка модуля на хосте остаётся отдельной привилегированной операцией.
- Проверка типа защищает чужой интерфейс с тем же именем, а `LinkSetUp` исключает
  создание настроенного, но выключенного устройства.
- В задаче 3 проверены компиляция Linux-кода и чистая сборка `wgtypes.Config`.
  **Новый `Netlink` ещё не проверен настоящим туннелем.** Проверка его сетевых
  операций и NAT остаётся `not-run` до E2E задачи 11; откат таблицы описывается
  runbook задачи 15. Измерения S1 не заменяют эти проверки реализации.
  (Это утверждение перечёркнуто датированной записью от 2026-11-05 ниже; абзац
  сохранён как часть истории решения, а не удалён.)
- 2026-11-05, поправка по итогам итогового ревью ветки `cycle/a3-node-runtime`.
  Предыдущий абзац остался в тексте историей: фазы туннеля, DNS и жизненного
  цикла подтверждены живым прогоном задачи 18 — журнал `task-18-e2e.log`
  каталога `.superpowers/sdd/2026-10-27-novavpn-cycle-a3-node-runtime` (60
  строк `ok`, отказов нет, стенд снят полностью; переснято на новом коде узла
  исправительным прогоном `fixreview-e2e.log` того же каталога). За
  подтверждением по-прежнему остаются худший случай интервала опроса при
  максимальном разбросе и поведение на реальной инфраструктуре — это задача 19,
  и строки `not-run` в статусе проверок это учитывают. Отдельно фиксируется
  смена поведения узла: поправки F1 и F2 исправительного захода (коммит
  `ed6a048`) меняют обработку незавершившегося цикла сходки — при отказе
  получения набора, при отказе снимка после ответа 304 и при отказе применения
  узел сбрасывает признак сходства и отправляет heartbeat со `stale=true`,
  а после отказа снимка следующий цикл идёт без ETag, то есть ждёт полный
  ответ 200, а не согласование по 304. Самовосстановление происходит через путь `Apply`
  (`internal/nodeagent/wg/applier.go`), где живут `EnsureLink` и
  `EnsureAddress`, а не через отдельную ветку кода. Описание поля `stale` в
  `api-spec/openapi.yaml` приведено к этой семантике в том же заходе.

## Отклонено

| Альтернатива | Почему |
|---|---|
| `wg-quick` / `syncconf` через subprocess | Shell из управляющего кода, нет живых метрик в выбранном API |
| Правка `iptables` / `nft` в общем ruleset | Затрагивает чужие правила и не даёт изолированного отката |
| Маршрут `AddressPool` через `netlink.RouteAdd` | Дублирует connected route адреса с маской пула |
| Изменение любого интерфейса с нужным именем | Одного имени недостаточно для подтверждения типа WireGuard |
