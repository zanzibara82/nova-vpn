# Развёртывание узла

Последовательность для одного VPS от чистого хоста до работающего узла. Каждый шаг
даёт команду и ожидаемый вывод: «убедитесь, что работает» здесь не встречается.
Секретов в файле нет — bootstrap-токены и приватные ключи живут файлами `0600` вне
репозитория.

## 1. Предусловия

- VPS с Debian 12 или Ubuntu 24.04, root-доступ по SSH;
- DNS-имя API, которое узел разрешит по HTTPS (например `api.novavpn.example`);
- SSH-ключ `ssh-ed25519`, файл лежит вне репозитория, наружу не печатается;
- доступ администратора API: создание сервера и выдача bootstrap-токена;
- собранные роли `novavpn_node` и `unbound` и работающая цель `make ansible-lint`.

## 2. Проверка хоста до установки

```bash
ssh root@HOST 'bash -s' -- api.novavpn.example < scripts/preflight.sh
```

Ожидание: строки вида `ok ...`, последняя — `хост готов`, код возврата 0. При любом
`FAIL` скрипт печатает `предварительная проверка не пройдена: установку не начинать`
и возвращает 1 — установку не начинать, разбор идёт по тексту отказа. Проверка
исходящего UDP/53 обязательна: конфигурация unbound в роли намеренно без форвардера,
и при порезанном 53 узел остался бы без DNS и без регистрации.

## 3. История репозитория проверяется перед публикацией

Рабочее дерево проверяет цель `make leakcheck` — она запускает `scripts/leakcheck.sh`
из этого репозитория. История коммитов проверяется отдельно и именно перед
публикацией репозитория, потому что дерево без секрета не гарантирует, что секрета
нет в прежних коммитах:

```bash
git log -p --all | grep -IE 'PRIVATE KEY'
```

Ожидание: пустой вывод и код 1. Команда перебирает весь дифф истории, поэтому
заметно медленнее остальных проверок и сознательно остаётся вне CI: её прогоняют
вручную перед тем, как репозиторий станет виден посторонним.

## 4. Сборка артефакта на сборочной машине

Сборка идёт в контейнере `golang:1.26-alpine` (как в `Dockerfile.node-agent`), а
`GOOS` и `GOARCH` задают потому, что собирает Windows/WSL, а работать узел будет на
Linux:

```bash
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -trimpath \
  -ldflags "-s -w -X main.version=$(git rev-parse --short HEAD)" \
  -o artifacts/novavpn-node-agent-linux-amd64 \
  ./services/node-agent/cmd/novavpn-node-agent
```

Ожидание: код 0 и файл `artifacts/novavpn-node-agent-linux-amd64`. Без `-X` узел
отчитывается версией `dev`, и вопрос «какая версия стоит на узле» остаётся без
ответа. `artifacts/` в `.gitignore`, бинарник в репозиторий не попадает.

## 5. Инвентарь

```bash
cd infrastructure/ansible
cp inventory.example.ini inventory.ini
```

Заполнить хост, `novavpn_node_api_url` (только `https`), `novavpn_node_pool`,
`novavpn_node_uplink_iface`, путь к ключу. `schema` и отпечаток ключа сверить с
панелью хостера. `inventory.ini` игнорируется `.gitignore`.

## 6. Первый прогон без регистрации

```bash
ansible-playbook infrastructure/ansible/site.yml -e novavpn_node_enroll=false
```

Ожидание: роль ставит пакеты, sysctl, таблицу nftables, юниты и бинарник, печатает
строку `public_key <BASE64>` и завершается кодом 0. Агент не запускается: регистрации
ещё нет, и это ожидаемое состояние, а не отказ.

## 7. Сервер и bootstrap-токен

Администратор создаёт сервер с напечатанным ключом и выдаёт bootstrap-токен. Токен
копируется на узел файлом `0600 root:root` по пути из переменной
`novavpn_node_bootstrap_file`. Значения по умолчанию у неё нет: в
`roles/novavpn_node/defaults/main.yml` она перечислена среди обязательных без значения,
а путь `/root/novavpn-bootstrap.token` стоит строкой в
`infrastructure/ansible/inventory.example.ini` — то есть приходит из инвентаря, а не из
роли, и менять его нужно там. В инвентаре ставится `novavpn_node_enroll=true`. Токен
одноразовый: повторная выдача — новый токен.

## 8. Второй прогон

```bash
ansible-playbook infrastructure/ansible/site.yml
```

Ожидание: узел регистрируется, бинарник обновляется, взводится таймер отката, агент
запускается, в конце прогон печатает `status`.

## 9. Проверка результата

| команда | ожидание |
| --- | --- |
| `journalctl -u novavpn-node-agent -n 30 --no-pager` | ни одной строки `узел не зарегистрирован` |
| `wg show wg0` | `listen-port 51820` и пиеры клиентов |
| `unbound-checkconf` | код 0, `no errors` |
| `dig @10.99.7.1 example.com` | ответ в секции ANSWER, rcode NOERROR |
| `curl ifconfig.me` с клиента | адрес узла, а не адрес клиента |

Слушать `0.0.0.0` — осознанный выбор: адрес туннеля появляется только после того,
как агент создаст устройство, а bind на ещё не существующий адрес это startup-гонка.
Плата за него — сокет виден и с публичного адреса, поэтому второй слой обязан закрыть
хостовый firewall оператора: `53/udp` и `53/tcp` с uplink дропаются, а `access-control`
отвечает `refuse` всем, кто не из пула. Проверка:

```bash
ssh root@HOST 'nft list ruleset | grep -E "hook input|udp dport 53"'
```

Ожидание: среди строк вывода есть правило hook input, дропающее `udp dport 53` и
`tcp dport 53` с uplink-интерфейса. Своя таблица роли цепочки `input` не имеет
(роль не меняет чужую политику молча), поэтому при отсутствии правила его добавляют
до подключения клиентов:

```bash
ssh root@HOST 'nft add rule inet filter input iif eth0 udp dport 53 drop; \
  nft add rule inet filter input iif eth0 tcp dport 53 drop'
```

Ожидание: код 0, та же проверка выше теперь печатает два дропа. Без этого узел
становится открытым рекурсором на публичном адресе.

## 10. Если через 180 с агент не активен

В журнале появляется запись о возврате `.prev` от `novavpn-rollback`. Разбор
начинают с `journalctl -u novavpn-node-agent` **до** повторного прогона: повторный
прогон затирает улики, а восстановленный бинарник скрывает, на чём упал новый.

## 11. Строка о прогоне

Результат фиксируется в `docs/testing-status.md`: либо `проверено <дата> <команда>`,
либо `not-run`. Молчание недопустимо: механизм, который существует в коде, но не
прогонялся, обязан быть виден как `not-run`.
